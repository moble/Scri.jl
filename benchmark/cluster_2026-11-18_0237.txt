# The cluster benchmark (2026-11-18): Scri.jl 1.0 and 0.1, and Python scri, under SLURM
# AMD EPYC 9654 96-Core Processor, on c0006; Julia 1.13.4
# 1.0: Scri 1.0.0; Chairmarks 1.3.1; OhMyThreads 0.8.9; Quaternionic 5.0.0; SphericalFunctions 3.0.3
# 0.1: Scri 0.1.0; Chairmarks 1.3.1; OhMyThreads 0.8.9; Quaternionic 4.5.0; SphericalFunctions 2.2.9
# Python: Python 3.15.2; scri 2024.0.14; numpy 2.5.5; numba 0.68.1
# Every case: 20000 time samples, ℓₘₐₓ = 8, a supertranslation with modes up to ℓ = 4
# (31 parameters), and an objective that compares the modes up to ℓ = 8.

Each case ran in a process of its own, inside a SLURM job that allocated it the
cores shown, one job after another.  Julia was started with one thread for each
allocated core, and BLAS and numba chose their own numbers of threads: with one
core, BLAS had 1 and numba had 1.  Each time is the least of several, in
seconds.  The gradient on 0.1 and in Python is by forward differences, which
take 32 evaluations of the objective; a time marked ~ was not measured, but is
32 times one evaluation, because the gradient would have taken longer than 600
seconds.  Memory is the peak resident set size of the process just after its
first call at full size, in gigabytes (2³⁰ bytes).
